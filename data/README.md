# Dataset Documentation

## Overview

This project uses the **`gbharti/finance-alpaca`** dataset to fine-tune a financial Q&A
instruction-following assistant. The dataset provides expert-quality financial answers
in the Alpaca format, making it well-suited for supervised fine-tuning (SFT).

## Input/Output Format

Each example follows the Alpaca format:

```json
{
  "instruction": "What is the difference between a Roth IRA and a Traditional IRA?",
  "input": "",
  "output": "A Roth IRA is funded with after-tax dollars, meaning withdrawals in retirement are tax-free..."
}
```

Some examples include an `input` field with additional context:

```json
{
  "instruction": "Calculate the compound interest.",
  "input": "Principal: $10,000, rate: 5% annually, period: 3 years",
  "output": "Using the formula A = P(1 + r/n)^(nt)..."
}
```

## Filtering Steps

The preprocessing pipeline applies filters in this order:

1. **Empty field filter** — Remove examples with empty `instruction` or `output`
2. **Output length filter** — Remove outputs with fewer than 5 words or more than 600 words
3. **Token length filter** — Remove examples where `format_for_training(example)` tokenizes to > 512 tokens
4. **Deduplication** — Remove duplicates using MD5 hash of `(instruction.lower(), input.lower())`

## Split Methodology

> [!IMPORTANT]
> The test set is **extracted first** before any train/val split to guarantee
> zero leakage between test and training data.

1. Shuffle the full filtered dataset with `seed=42`
2. Extract **10%** as the held-out test set (never used in training or validation)
3. From the remaining 90%, extract **~5.6%** as the validation set (5% of total)
4. The rest becomes the training set (~84.4% of total)

A hard `AssertionError` guard (`_verify_no_overlap`) checks all three split pairs
(train↔val, train↔test, val↔test) using instruction+input hashes before saving.

## Data Quality Notes

- **Synthetic origin**: Finance-alpaca outputs were generated by GPT-4. High coverage
  but not guaranteed to be expert-level.
- **Not 100% finance**: the dataset merges finance Q&A with some generic Alpaca
  instructions (e.g. "Generate 5 questions about Men's fashion" appears in the test
  split). No topic filter is applied — worth adding before a production run.
- **Same question, different answer**: the 10,026 rows removed by exact dedup share an
  `(instruction, input)` with another row but frequently have a *different* `output`.
  The pipeline keeps the first occurrence (`deduplicate`, `keep first`).
- **Near-duplicates**: exact + normalized (punctuation/whitespace-insensitive) dedup
  only — 0 normalized collisions found. Semantic paraphrases are not detected.
- **Length variability**: Output lengths vary from 5 words (post-filter minimum) to 600
  words. Very long outputs tend to be more detailed but may exceed context windows.
- **Domain skew**: The dataset skews toward US-centric personal finance concepts.

## Reproducing the Data Pipeline

```bash
# Full pipeline (includes slow token-length filtering)
python scripts/prepare_data.py \
  --model-name Qwen/Qwen2.5-1.5B \
  --max-seq-len 512 \
  --test-frac 0.10 \
  --val-frac 0.05 \
  --seed 42

# Fast mode (skips token-length filtering — for development only)
python scripts/prepare_data.py \
  --model-name Qwen/Qwen2.5-1.5B \
  --skip-token-filter \
  --seed 42
```

> [!CAUTION]
> **Never use `test.json` during training or hyperparameter tuning.**
> It exists solely for final evaluation to measure real-world generalization.
